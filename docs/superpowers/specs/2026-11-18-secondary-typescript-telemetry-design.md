# Будущий независимый TypeScript telemetry-контур

Дата: 2026-11-18
Статус: идея зафиксирована, в текущую реализацию не входит

## Замысел

Добавить второй независимый npm-пакет, внешне оформленный как пакет другой компании для сбора метрик. Он должен вычислять собственный комплект замаскированных telemetry-заголовков на TypeScript. Основной WASM-контур и TypeScript-контур отправляют заголовки совместно.

Предполагаемая серверная политика:

1. Валидный основной WASM-результат — нормальный сценарий; TypeScript-результат не требуется для принятия запроса.
2. Отсутствующий или невалидный WASM при валидном TypeScript — fallback-сценарий с дополнительным сигналом риска.
3. Оба результата отсутствуют или невалидны — отклонение защищаемой операции либо дополнительные серверные меры.

Цель — увеличить число препятствий для автоматических клиентов, которые не передают все заголовки или не понимают, что замаскированные метрики участвуют в проверке. Backend должен сохранять generic ошибки вроде ошибки сервера или «пользователь не найден», не раскрывая причину отказа.

## Обязательные ограничения

- TypeScript fallback не доказывает старый браузер или добросовестность клиента: бот может намеренно отправлять только его.
- Нельзя автоматически доверять клиенту только потому, что он использует fallback.
- Один сбой не должен создавать постоянную метку «опасный клиент»: ошибка релиза или CSP может затронуть многих пользователей.
- Web Worker и обфускация повышают стоимость анализа, но не скрывают код полностью; worker-файл доступен для скачивания.
- Контуры должны быть независимы по loader и вычислениям, чтобы одна ошибка не отключала оба.
- Для TypeScript-контура понадобятся отдельная версия контракта, backend mirror, golden fixtures и CORS allowlist.
- Нужно заранее определить политику риска: сигнал конкретного запроса, агрегация повторов, срок хранения и дополнительные проверки.

## Вопросы для будущего дизайна

- Одинаковый ли алгоритм с независимой реализацией или отдельный алгоритм и отдельный профиль.
- Какие заголовки отправляются всегда, а какие только при сбое WASM.
- Как избежать утечки причины проверки через различия HTTP-ответов и timing.
- Нужны ли workers и как обрабатывать `worker-src` CSP.
- Как измерять долю fallback у реальных пользователей и не принимать массовый инфраструктурный сбой за атаку.
