# Дизайн руководства по сборке и подключению пакета

## Назначение

Дать разработчику пошаговую инструкцию по подготовке `@company/marketing-telemetry` и подключению его к произвольному Angular-приложению. Документ должен поддерживать как машину с установленным Rust, так и сценарии, где WASM и npm-артефакты уже собраны.

## Цели

- Описать полный путь от Rust-исходников до локального npm-архива и Angular production-сборки.
- Разделить зависимости по сценариям: исходники, готовые WASM-артефакты, готовый npm-пакет.
- Точно перечислить generated-файлы, необходимые при переносе предсобранного WASM.
- Показать локальную установку через `.tgz` и каталог, публичный API `TelemetrySdk`, DOM-якорь и передачу заголовков в HTTP-запрос.
- Добавить CI/CD-порядок, проверки содержимого архива и разбор типичных ошибок.

## Нецели

- Не менять Rust, TypeScript, Angular-код, package manifest или build scripts.
- Не описывать публикацию в npm registry и отложенный PHP backend как обязательную часть клиентского деплоя.
- Не предлагать копирование `pixel.wasm` в Angular `assets`: runtime использует base64 из `dist`.

## Ограничения и факты проекта

- Полная сборка запускается из корня репозитория и требует Node.js `^22.12.0 || >=24.0.0`, npm, Rust stable, target `wasm32-unknown-unknown` и `wasm-pack`.
- `npm run build:wasm` создаёт `packages/marketing-telemetry/pkg/` и `packages/marketing-telemetry/src/generated-pixel.ts`.
- `npm run build --workspace @company/marketing-telemetry` создаёт `dist/`; `npm pack --workspace @company/marketing-telemetry` создаёт локальный `.tgz`.
- Raw `pixel.wasm` не входит в npm-архив. Для runtime нужны base64 в скомпилированном `dist` и generated JS glue из `pkg`.
- Angular-потребителю готового архива Rust, `wasm-pack` и исходники crate не нужны.

## Подходы

1. **Отдельное руководство `docs/deployment.md` со ссылками из существующих документов — выбрано.** Оно отделяет инструкцию по доставке и интеграции от карты исходников в `frontend-guide.md` и поддерживает все три сценария в одном месте.
2. **Расширить только `docs/frontend-guide.md`.** Меньше файлов, но смешивает разработку репозитория с интеграцией готового пакета и делает длинный документ ещё тяжелее.
3. **Описать всё только в `README.md`.** Даёт быстрый доступ, но превращает обзор проекта в громоздкий эксплуатационный мануал.

## Структура выбранного решения

`docs/deployment.md` содержит матрицу сценариев и зависимостей, полную сборку, перенос предсобранных артефактов, создание и проверку `.tgz`, два способа локальной установки, Angular-пример, CI/CD-последовательность и troubleshooting. `README.md` и `docs/frontend-guide.md` получают короткие ссылки на новое руководство.
