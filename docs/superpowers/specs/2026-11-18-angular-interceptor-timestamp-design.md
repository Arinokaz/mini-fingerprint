# Angular interceptor и точный timestamp — дизайн

Дата: 2026-11-18

## Назначение

Превратить существующий npm-пакет в Angular-only интеграцию, которая автоматически добавляет telemetry-заголовки к каждому запросу `HttpClient`. Перейти от трёхминутных окон к текущему Unix timestamp в секундах, чтобы backend мог точно ограничивать возраст результата.

## Цели

- Один npm-пакет `@company/marketing-telemetry`; Angular-зависимости объявляются через `peerDependencies`.
- Экспортировать `marketingTelemetryInterceptor: HttpInterceptorFn` для регистрации через `provideHttpClient(withInterceptors(...))`.
- Обрабатывать все запросы `HttpClient`, без списка login/register и без специальных свойств этих форм.
- Передавать в WASM только путь URL без origin, query и fragment.
- Вычислять заголовки заново для каждого прохождения interceptor; кэшировать только инициализацию WASM.
- Использовать один application-wide `TelemetrySdk` через root `InjectionToken`.
- Не реализовывать retry и JavaScript fallback.
- При ошибке получения заголовков отправить исходный запрос один раз без telemetry-заголовков; HTTP-ошибки downstream не перехватывать как ошибки генерации.
- Сохранить DOM fallback `telemetry.unresolved.v1`; backend не должен принимать его как настроенный marker.

## Timestamp-контракт

`cv1` пока является pre-release контрактом без реализованного PHP backend, поэтому временная семантика меняется без добавления параллельного профиля.

Клиент использует `timestamp = floor(Date.now() / 1000)`. `pulse` кодирует этот timestamp, а `score` вычисляется из journey, touchpoint, canonical properties и timestamp. Граничный буфер и выбор текущего/следующего окна удаляются.

PHP должен восстановить timestamp из `pulse`, проверить каноничность и применять конфигурируемую серверную политику. Рекомендуемые начальные значения: прошлое не более 30 секунд, будущее не более 5 секунд. Сам PHP mirror остаётся вне текущего объёма, но pseudocode и документация обновляются.

## Рассмотренные подходы

- **Выбрано:** существующий пакет становится Angular-only и экспортирует functional interceptor. Это даёт один архив и минимальную настройку приложения.
- Отдельный базовый и отдельный Angular adapter: сохраняет универсальность, но противоречит требованию одного пакета.
- Ручной вызов `TelemetrySdk` в каждом сервисе: дублирует интеграцию и допускает пропущенные заголовки.
- JavaScript fallback: отложен; он раскрывает вторую реализацию алгоритма и требует отдельного анализа.
- Nonce: не используется. Timestamp не гарантирует уникальность внутри одной секунды и не привязывает результат к пользователю.

## Границы текущего объёма

- Нативный `fetch` в demo заменяется на Angular `HttpClient`.
- Внешние запросы не выделяются endpoint-фильтрами: interceptor применяется ко всем `HttpClient`-запросам приложения.
- PHP implementation, второй TypeScript npm-пакет, workers, CSP-изменения и поддержка старых браузеров не реализуются.
- Полные browser/release проверки выполняются отдельным финальным регрессом после быстрых изменений.

## Проверяемые инварианты

- Одинаковые входы и одинаковая секунда дают одинаковый результат; другая секунда меняет `pulse` и `score`.
- Query и fragment не участвуют в journey.
- Успешная генерация добавляет полный комплект из пяти заголовков.
- Ошибка генерации не добавляет часть комплекта и не блокирует исходный запрос.
- Ошибка backend не вызывает повторную отправку.
- Отсутствие DOM marker не вызывает исключение.
