# Дизайн внутренней документации для PHP-разработчика

## Назначение

Дать владельцу проекта, знакомому с PHP, но не с Rust и мало знакомому с TypeScript/Angular, понятное описание внутреннего устройства системы. Документация должна помогать формулировать рефакторинг и доработки по именам классов, методов, входных данных, результатов и ограничений.

## Цели

- Дать краткий входной документ с PHP-аналогиями, словарём и правилом чтения кода.
- Показать end-to-end поток от Angular submit до WASM и HTTP-заголовков, включая embedded/lazy-различия.
- Описать каждый TypeScript source module, класс, публичный метод и важную внутреннюю функцию пакета.
- Описать каждый Rust module, его назначение, основные функции, структуры, этапы вычисления и fallback/error behavior.
- Описать Angular demo component/service/template и их роль в интеграции.
- Для важных сущностей фиксировать: назначение, где вызывается, вход/результат, логику, side effects, ошибки/fallback, инварианты, безопасные направления изменения и связанные тесты.
- Связать документы с нормативным `contracts/conversion-v1.md`, не дублируя таблицы/весь псевдокод без необходимости.

## Нецели и ограничения

- Не менять исходный код, comments, build configuration или package artifacts.
- Не включать внутреннюю документацию в npm-архивы или production static files.
- Не заменять чтение нормативного контракта кратким пересказом при противоречии: контракт первичен.
- Не описывать generated `pkg/`, `dist/` и `generated-pixel.ts` как вручную редактируемые источники.
- Не делать безопасность зависимой от маскировки: явно отметить границы этой модели.
- Не выполнять commit, push или другие действия публикации Git; пользователь сам управляет итоговым Git-этапом.

## Подходы

1. **Отдельная внутренняя документация + существующие исходные комментарии — выбрано.** Подробные объяснения не попадают в browser artifact; существующая prepack-минификация удаляет комментарии независимо от Angular.
2. **Только комментарии в коде — отклонено.** Не дают общей карты, PHP-аналогий и удобного описания связей между модулями.
3. **Один большой файл — отклонено.** Затрудняет поиск конкретного Rust/TypeScript/Angular-компонента.

## Структура

- `docs/php-developer-guide.md` — точка входа, аналогии, как читать остальные документы и формулировать изменения.
- `docs/architecture.md` — компоненты, поток выполнения, доверенные/недоверенные границы, embedded/lazy.
- `docs/modules/telemetry-package.md` — TypeScript API и внутренняя логика пакета, включая build/release scripts на обзорном уровне.
- `docs/modules/rust-wasm.md` — Rust crate и все source-модули.
- `docs/modules/angular-demo.md` — Angular component/service/config/template.
- Ссылки из `README.md`, `docs/frontend-guide.md` и `docs/deployment.md`.

## Проверка

Каждый документ сверяется с реальными исходниками. Проверяются внутренние Markdown-ссылки, покрытие списка source files, отсутствие изменений кода и `git diff --check`. Отдельное ревью проверяет точность и понятность для PHP-разработчика. Локальные изменения остаются без commit.
