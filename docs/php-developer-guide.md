# Руководство для PHP-разработчика

Этот документ — точка входа для разработчика, который хорошо знает PHP, но хочет изменять Angular/TypeScript/Rust-проект без предварительного изучения каждой технологии.

## 1. С чего начать чтение

Рекомендуемый порядок:

1. [`architecture.md`](architecture.md) — как компоненты связаны и что происходит при login/register.
2. [`modules/angular-demo.md`](modules/angular-demo.md) — как демонстрационная страница вызывает пакет.
3. [`modules/telemetry-package.md`](modules/telemetry-package.md) — классы и методы TypeScript/npm-пакета.
4. [`modules/rust-wasm.md`](modules/rust-wasm.md) — модули и функции Rust/WASM.
5. [`../contracts/conversion-v2.md`](../contracts/conversion-v2.md) — активный алгоритм `cv2`, включая наследуемые общие операции `cv1`; при расхождении с кратким описанием контракты являются первичными.
6. [`deployment.md`](deployment.md) — только когда нужно собрать или выдать пакет фронтендам.

## 2. Карта технологий

| Технология | Роль в проекте | Привычная PHP-аналогия |
|---|---|---|
| Angular | Страница, форма, компонент и сервис отправки | Шаблон + класс страницы + application service |
| TypeScript | Публичный API пакета, проверка ответа WASM, формирование заголовков | Статически типизированный PHP-сервис |
| Rust | Основные вычисления, чтение DOM и времени | Отдельная библиотека с алгоритмом |
| WebAssembly | Форма, в которой Rust выполняется в браузере | Скомпилированный модуль, вызываемый из JS |
| npm | Установка TypeScript-пакета в Angular | Composer |
| Cargo | Зависимости и сборка Rust crate | Composer для Rust |

Это аналогии для ориентации, а не утверждение полной эквивалентности технологий.

## 3. Минимальный словарь

### TypeScript

- `interface` — описывает обязательную форму объекта, похоже на набор требований к DTO.
- `type` — псевдоним типа, например `RuntimeLoader = () => Promise<PixelRuntime>`.
- `Record<string, string>` — ассоциативный объект/массив со строковыми ключами и значениями.
- `Promise<T>` — результат асинхронной операции, который появится позже; результат читается через `await`.
- `async` — функция возвращает `Promise`.
- `private readonly` — свойство доступно только внутри класса и не переназначается после инициализации.
- `unknown` — неизвестный тип, который сначала нужно проверить; безопаснее `any`.
- `.d.ts` — declarations с типами для редактора/TypeScript, браузер их не выполняет.

### Angular

- **Component** хранит состояние шаблона и обрабатывает действия пользователя.
- **Service** содержит прикладную операцию, например подготовку и отправку login-запроса.
- **Template** — HTML с Angular-привязками вроде `(click)` и `[attr.data-tag]`.
- `signal(...)` — реактивное состояние; его изменение обновляет представление.
- `inject(...)` — получение зависимости через Angular DI, аналог получения сервиса из контейнера.

### Rust

- `struct` — данные с именованными полями; похоже на простой PHP-класс/DTO.
- `impl` — блок методов для `struct` или другого типа.
- `trait` — контракт поведения, концептуально похож на PHP interface.
- `enum` — один из перечисленных вариантов значения.
- `String` — владеемая изменяемая строка; `&str` — заимствованное строковое представление.
- `Vec<T>` — динамический список значений типа `T`.
- `[T; N]` — массив фиксированной длины `N`.
- `Option<T>` — значение есть (`Some`) или отсутствует (`None`); ближе к nullable, но отсутствие надо обработать явно.
- `Result<T, E>` — успех (`Ok`) или ошибка (`Err`) как возвращаемое значение, а не автоматически выброшенное исключение.
- `pub` — делает элемент доступным за пределами текущего модуля.
- `crate` — отдельный Rust-пакет; здесь это `funnel-wasm`.

## 4. Исходники и результат сборки

Не всё в репозитории предназначено для ручного редактирования.

### Исходники

```text
apps/demo-web/src/**
packages/marketing-telemetry/src/*.ts
packages/marketing-telemetry/scripts/*.mjs
crates/funnel-wasm/src/*.rs
contracts/conversion-v1.md
```

### Generated-результаты

```text
packages/marketing-telemetry/pkg/**                 # wasm-pack
packages/marketing-telemetry/src/generated-pixel.ts # build-wasm.mjs
packages/marketing-telemetry/dist/**                # declarations + минифицированный JS
apps/demo-web/dist/**                               # Angular
release/**                                          # npm-архивы и size report
```

Их не нужно редактировать вручную. Изменяйте исходник, затем повторяйте соответствующую сборку.

## 5. Где находится подробная внутренняя документация

Документация в `docs/` предназначена только для разработчиков. Она:

- не импортируется Angular;
- не входит в список npm `files`;
- не копируется в Angular `assets`;
- не загружается браузером.

В исходниках могут быть комментарии. При сборке npm-пакета TypeScript/esbuild удаляют комментарии и минифицируют JS **до** создания `.tgz`, поэтому результат не зависит от настроек минификации у frontend-команды.

## 6. Как читать карточку класса или метода

Для важных элементов module guides используют одни и те же вопросы:

- **Зачем нужен** — какую ответственность имеет.
- **Где вызывается** — кто является непосредственным потребителем.
- **Вход/результат** — что передаётся и что возвращается.
- **Логика** — основные шаги без дословного копирования кода.
- **Side effects** — DOM, время, сеть, загрузка chunk или WebAssembly.
- **Ошибки/fallback** — что происходит при нештатном входе.
- **Инварианты** — что нельзя изменить без синхронного изменения контракта/backend.
- **Тесты** — какие проверки должны остаться зелёными.

## 7. Как сформулировать следующую доработку

Полезный шаблон:

```text
Файл/модуль: packages/marketing-telemetry/src/conversion.ts
Класс/метод: TelemetrySdk.getConversionHeaders()
Сейчас: метод получает путь и свойства, передаёт scorePrefix в WASM и возвращает шесть заголовков.
Нужно: <новое наблюдаемое поведение>.
Сохранить: lazy initialization, шесть заголовков, clickId и существующий порядок свойств.
Изменить контракт/backend: да/нет; если да — какое именно правило cv2.
Новые случаи: <пустые значения, ошибки, границы, повторные вызовы>.
Проверка: <какой результат должен получиться и какой test это подтвердит>.
```

Если точное место изменения пока неизвестно, достаточно описать вход и ожидаемый результат. Карта модулей помогает затем найти ответственный компонент.

## 8. Важная граница безопасности

Клиентский JS/WASM, минификация и маркетинговые названия повышают стоимость анализа, но браузерная среда контролируется клиентом. Base64 можно декодировать, JS и WASM можно исследовать, запросы можно повторить.

Поэтому маскировка не заменяет серверную проверку, ограничение brute-force и другие server-side меры. Текущий PHP mirror/endpoints отложены; псевдокод находится в [`php-mirror-pseudocode.md`](php-mirror-pseudocode.md).
