# Контракт `conversion-v1` (`cv1`)

## 1. Назначение и границы

`cv1` определяет детерминированное преобразование API-пути, DOM-атрибута, дополнительных свойств и Unix timestamp в секундах в значение из 64 строчных hex-символов. Готовые хеш-функции и HMAC не используются.

Это обфускационный механизм, а не криптографическая аутентификация браузера. Wasm и DOM доступны атакующему. Timestamp не запрещает повторную отправку запроса внутри допустимого серверного интервала и не гарантирует уникальность значений разных запросов в одну секунду.

Нормативные слова «должен» и «запрещено» обязательны для Rust/Wasm и PHP 8.4. Эталонные значения находятся в `tests/fixtures/conversion-v1.json`.

## 2. Базовые типы и операции

Все рабочие состояния состоят из восьми беззнаковых 32-битных слов (`u32`). Любая операция сохраняет только младшие 32 бита.

- `add32(a, b) = (a + b) mod 2^32`.
- `sub32(a, b) = (a - b) mod 2^32`.
- `mul32(a, b) = (a × b) mod 2^32`.
- `rotl32(a, n)` — циклический сдвиг `a` влево на `n mod 32` бит.
- `rotr32(a, n) = rotl32(a, -n)`.
- `u32le(n)` — четыре байта `n` в little-endian.
- `u64le(n)` — восемь байтов `n` в little-endian.

В Rust используется обычная `u32`-арифметика с `wrapping_*`. В PHP каждое слово представляется целым от `0` до `4294967295`. Запрещены `float`, GMP и прямое 32-битное умножение с последующим маскированием: `mul32` реализуется через 16-битные части.

В fixtures слово записывается как восемь hex-символов его численного значения. При сериализации кадра в итоговое значение каждое слово записывается через `u32le`.

### 3.4. Перестановка и замена байтов

```text
P = [3, 7, 1, 6, 0, 4, 2, 5]
S = [6, 11, 3, 13, 8, 0, 15, 5, 10, 2, 12, 7, 1, 14, 4, 9]
```

Для байта `b` функция замены использует младший и старший полубайты:

```text
substitute(b) = S[b & 0x0f] | (S[(b >> 4) & 0x0f] << 4)
```

## 4. Входные данные

### 4.1. API-путь (`journey`)

Angular явно передаёт путь, например `/api/auth/login`. Путь обязан быть корректной UTF-8 строкой длиной от 1 до 512 байт, начинаться с `/` и не содержать query string, fragment или NUL. `window.location.pathname` вместо API-пути не используется.

### 4.2. DOM-атрибут (`touchpoint`)

Wasm выполняет `document.query_selector_all("span.telemetrics_click")`.

Значение атрибута `data-tag` используется только если найден ровно один элемент, атрибут существует, не пуст и занимает не более 256 байт UTF-8. Во всех остальных случаях, включая отсутствие `document`, выбирается строка:

```text
telemetry.unresolved.v1
```

Отсутствие или неоднозначность DOM-элемента не вызывает исключение и не прерывает вычисление. PHP использует ожидаемый `data-tag` из собственной конфигурации, а не значение, присланное клиентом.

### 4.3. Дополнительные свойства (`properties`)

На границе Wasm свойства представляются JSON-массивом пар:

```json
[["z.last","привет"],["a.first","value:with:colon"],["empty",""]]
```

Требования:

- не более 32 пар и не более 4096 байт входного JSON;
- имя — ASCII-строка, соответствующая `[a-z0-9_.-]{1,64}`;
- значение — UTF-8 строка не более 512 байт;
- имена уникальны; дубликаты запрещены даже при разном порядке пар;
- имена `sys.journey`, `sys.touchpoint`, `sys.pulse`, `sys.profile` зарезервированы и запрещены;
- вложенные массивы, объекты, числа, boolean и `null` в качестве имени или значения запрещены.

Пары сортируются по байтам имён в возрастающем порядке. Канонический бинарный поток содержит для каждой пары:

```text
u32le(длина имени) || имя || u32le(длина значения) || значение
```

Канонический JSON — отсортированный массив пар без пробелов. В строках `"` и `\` экранируются как `\"` и `\\`; используются стандартные короткие escape-последовательности `\b`, `\t`, `\n`, `\f`, `\r`; остальные символы U+0000–U+001F записываются как `\u00xx` со строчными hex. `/` не экранируется, не-ASCII символы передаются непосредственно в UTF-8.

Для HTTP канонический JSON кодируется base64url без `=`. PHP строго декодирует base64url, повторно разбирает JSON и сверяет его каноническую форму.

## 5. Операции кадра

### 5.1. Поглощение `absorb(frame, domain, payload, rounds)`

Формируется поток:

```text
data = domain(один байт) || u32le(len(payload)) || payload
```

Для каждого байта `b` с нулевым индексом `i` последовательно выполняется:

```text
lane = i mod 8
s = substitute((b + domain + (i mod 251)) mod 256)
r = (i mod 31) + 1
m = mul32(frame[lane] XOR (s OR ((i mod 256) << 8)), M[lane])
frame[lane] = add32(rotl32(m, r), A[(lane + i) mod 8])
other = (lane + 3) mod 8
frame[other] = frame[other] XOR
    rotl32(add32(s, i), ((lane × 3 + i) mod 31) + 1)
```

Изменения `frame` видны следующим итерациям. После обработки всех байтов выполняется `diffuse(frame, rounds)`.

### 5.2. Рассеивание `diffuse(frame, rounds)`

Для каждого раунда `r` сначала сохраняется копия `old = frame`. Новый кадр целиком вычисляется из `old`, а не из частично обновлённых слов:

```text
для i от 0 до 7:
    j = P[i]
    a = old[j]
    b = old[(j + 3) mod 8]
    mixed = mul32(
        a XOR rotl32(b, ((r + i) mod 31) + 1),
        M[(i + r) mod 8]
    )
    frame[i] = add32(
        rotl32(mixed, ((i × 5 + r × 3) mod 31) + 1),
        A[(i + 2 × r) mod 8]
    ) XOR old[(i + 1) mod 8]
```

## 6. Точный timestamp и обратимый `pulse`

### 6.1. Выбор timestamp

Wasm получает миллисекунды через `js_sys::Date::now()` и использует `timestamp = floor(nowMilliseconds / 1000)`. Нефинитное или отрицательное время отклоняется. Временные окна и клиентский boundary buffer не применяются.

PHP восстанавливает timestamp и сравнивает его с серверным Unix time. Рекомендуемая начальная политика: `timestamp >= serverTime - 30` и `timestamp <= serverTime + 5`. Оба допуска должны быть конфигурацией backend и одинаково проверяться на границах. Timestamp не является nonce: запросы с одинаковыми входами в одну секунду имеют одинаковый результат.

### 6.2. Константы

```text
K0 = a53c9e17
K1 = 6d2b79f5
C0 = 9e3779b9
C1 = 7f4a7c15
```

### 6.3. Кодирование

Для `timestamp: u64` используются младшее и старшее 32-битные слова:

```text
a = low32(timestamp) XOR K0
b = high32(timestamp) XOR K1
c = add32(a, rotl32(b, 7))
d = b
e = c
f = add32(d, rotl32(c, 13))
out0 = e XOR C0
out1 = f XOR C1
pulse = hex(u32le(out0) || u32le(out1))
```

`pulse` содержит ровно 16 строчных hex-символов.

### 6.4. Декодирование

```text
e = out0 XOR C0
f = out1 XOR C1
d = sub32(f, rotl32(e, 13))
c = e
a = sub32(c, rotl32(d, 7))
b = d
timestamp = (a XOR K0) OR ((b XOR K1) << 32)
```

PHP также повторно кодирует восстановленный timestamp и отклоняет неканоническое представление `pulse`.

## 7. Последовательность этапов

```text
frame = INITIAL
frame = absorb(frame, 0x4a, utf8(journey), 4)
frame = absorb(frame, 0xb7, utf8(selectedTouchpoint), 4)
frame = absorb(frame, 0xd9, canonicalPropertyBytes, 4)
pulsePayload = u32le(out0) || u32le(out1) || u64le(selectedTimestamp)
frame = absorb(frame, 0xe3, pulsePayload, 8)
score = hex(u32le(frame[0]) || ... || u32le(frame[7]))
```

Пустой список свойств всё равно проходит этап с пустым `payload`: домен и нулевая длина изменяют кадр.

Внутри рабочих этапов разрешены дополнительные bounded-вычисления, временные переменные и runtime-ветвления. Они не входят в нормативный результат и не должны изменять кадр после завершения этапа. Каждая такая ветка проверяется на эквивалентность тестами.

## 8. Заголовки и серверная проверка

| Заголовок | Содержимое |
|---|---|
| `X-GA-Measurement-Id` | `cv1` |
| `X-GA-Session-Id` | `pulse`, 16 hex |
| `X-Amplitude-Device-Id` | `score`, 64 hex |
| `X-Amplitude-Session-Properties` | base64url канонического JSON свойств без padding |
| `X-YM-Counter-Client` | статический телеметрийный шум |

PHP:

1. Проверяет размер и формат всех значений и профиль `cv1`.
2. Декодирует `pulse`, восстанавливает timestamp, проверяет каноничность и допустимый возраст/погрешность времени.
3. Использует фактический путь текущего маршрута и ожидаемый серверный `data-tag`.
4. Канонизирует свойства и повторяет все этапы.
5. Сравнивает результат через `hash_equals()`.
6. Возвращает одинаковый `403` для любой ошибки без раскрытия причины.

Совпадение с резервным DOM-значением не является ожидаемым серверным результатом и в демонстрационной конфигурации должно быть отклонено.
